## Pack + run

```bash
python -m rwkv_ssd.tools.pack_runtime ^
  --input test_model/rwkv7-g1d-0.1b-20260129-ctx8192.pth ^
  --output test_model/runtime_pack

python -m rwkv_ssd.tools.verify_pack test_model/runtime_pack

python -m app.cli ^
  --model test_model/runtime_pack ^
  --checkpoint test_model/rwkv7-g1d-0.1b-20260129-ctx8192.pth ^
  --backend chatrwkv ^
  --mode resident ^
  --strategy "cpu bf16" ^
  --max-tokens 16 ^
  --prompt "Hello" ^
  --progress --log-level INFO
```

**Resident** mode loads the full `.pth` (~10–30 s on CPU). **Streaming** uses skeleton load (globals from pack only, ~2 s) and streams block weights from `weights.bin` each token. Close the quote on `--prompt "..."` in PowerShell.

```bash
python -m app.cli ^
  --model test_model/runtime_pack ^
  --checkpoint test_model/rwkv7-g1d-0.1b-20260129-ctx8192.pth ^
  --backend chatrwkv ^
  --mode streaming ^
  --strategy "cpu bf16" ^
  --max-tokens 8 ^
  --prompt "Hello" ^
  --metrics-csv layers.csv

python bench/bench_chatrwkv.py
python bench/bench_io.py --model test_model/runtime_pack
```

## Fast throughput bench (0.01B default)

```bash
python bench/bench_throughput.py ^
  --backend chatrwkv ^
  --strategy "cpu bf16" ^
  --max-tokens 32

python bench/bench_throughput.py --heavy --backend chatrwkv --strategy "cpu bf16"
```

`bench_throughput.py` defaults to `runtime_pack_0.01b` + `rwkv7-g1d-0.01b-bench.pth`. Use `--heavy` for 0.1B.

**Streaming throughput (v0.6.7+):** `--stream-layer-cache` retains layers in `z`; after warm decode, **promote** lifts retention to all blocks (FP16 ≈ resident on 0.1B). Trinity eval packs live under `trinity_eval/` — compare with `bench/bench_tok_s_compare.py` (refresh `tok_s_compare.json`; stored file is pre-promote).

```bash
python -m app.cli ^
  --model test_model/trinity_eval/fp16_grouped ^
  --checkpoint test_model/rwkv7-g1d-0.1b-20260129-ctx8192.pth ^
  --backend chatrwkv --mode streaming --stream-layer-cache ^
  --strategy "cpu bf16" --state-cache ^
  --system-prefix "You are a helpful assistant." "Hello"
```

Flags: `--low-ram` · `--ram-budget-gb 10` · `--decode-disk-cache` · see [`deploy/README.md`](../deploy/README.md).

M5 codec variants (local, gitignored):

```bash
python -m rwkv_ssd.tools.eval_m5_codec ^
  --build test_model/rwkv7-g1d-0.01b-bench.pth ^
  --output test_model/packs_0.01b
```

Promotion gate: ≥1.3× smaller `weights.bin` vs none; golden via `pytest tests/test_pack_codec_golden.py`.

ChatRWKV is auto-discovered from `test_model/ChatRWKV` if present. Set `CHATRWKV_ROOT` to override.

Requires `RWKV_V7_ON=1` (set automatically for RWKV-7 checkpoints).

## RWKV7a DeepEmbed-v1

```powershell
python -m rwkv_ssd.tools.pack_runtime `
  --input test_model/rwkv7a-g1d-0.1b-20260212-ctx8192.pth `
  --output test_model/runtime_pack_rwkv7a_v1
python -m rwkv_ssd.tools.verify_pack test_model/runtime_pack_rwkv7a_v1
python -m app.cli --model test_model/runtime_pack_rwkv7a_v1 `
  --checkpoint test_model/rwkv7a-g1d-0.1b-20260212-ctx8192.pth `
  --backend chatrwkv --mode streaming --strategy "cpu bf16" `
  --prompt "Hi" --max-tokens 4
```

ChatRWKV is imported with `RWKV_DE_VERSION=1`. This variant keeps
`s_emb`/`s_emb_x` in the ordinary packed tensors and does not create the older
qkv/DEA `DeepEmbed.bin` sidecar. The opt-in parity test is
`tests/test_rwkv7a_deepembed.py`.

The small Mamba-2 and Transformer checks use fixed token IDs deliberately so
the dependency-light reference harness does not claim Hugging Face tokenizer
compatibility:

```powershell
.venv-cpu\Scripts\python.exe -m pytest -q `
  --basetemp .pytest-tmp\codex-real-sequence `
  tests/test_real_sequence_models.py -m integration
```
